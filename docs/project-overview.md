# Spotify 트랙 인기 예측과 장르별 음악 속성 조정 제안

UNIST CSE36501 Deep Learning · 2026년 가을 · GyeongWon Cho, HyeonGyu Hwang

스트리밍 카탈로그가 포화되면서 수많은 곡이 청취자의 관심을 두고 경쟁한다. 아티스트와 레이블이 제작 단계에서 내려야 할 결정은 곡 고유의 사운드를 어디까지 유지하고, 어떤 속성을 얼마나 바꿀 것인가다. 이 프로젝트는 오디오 속성과 장르로 Spotify 인기 지수(0~100점)를 예측하고, 어떤 속성이 해당 곡의 예측에 기여했는지 설명한다. 최종 산출물인 **곡별 조언 카드**에는 유지할 속성, 실행 가능한 변경안, 현재 장르를 유지하거나 스타일을 전환할 때의 예상 인기 점수 변화가 담긴다. [1단계 프로젝트 제안서, 2~5쪽](prepare/proposal_music_popularity_xai-1.pdf)

## 문제 정의와 연구 질문

분석 단위는 트랙이며 목표값은 데이터 수집 시점의 인기 지수다. 오디오 파형을 직접 처리하지 않고 곡마다 계산된 음악 속성을 사용하는 표 형식 회귀 문제다. 장르를 포함하는 이유는 같은 속성도 장르에 따라 예측에 기여하는 정도와 방향이 달라질 수 있기 때문이다. 기반 연구는 튜닝한 랜덤 포레스트(RF), SHAP·LIME 설명, 제약을 둔 베이지안 최적화를 연결했다. 이 프로젝트는 예측기에 표 형식 Transformer를 도입하고, 장르를 학습 가능한 벡터로 표현할 때 얻는 효과를 검증한다. [Zhang 외, Journal of Business Research 211, 116197 (2026)](https://doi.org/10.1016/j.jbusres.2026.116197)

| 연구 질문 | 판단 방법 |
|---|---|
| RQ1. 모델 구조를 바꾸면 예측력이 높아지는가? | 같은 입력과 분할에서 Transformer와 튜닝한 RF의 오차를 비교한다. 제안서가 인용한 RF의 R² 약 0.7416, RMSE 약 9.299는 문헌 참조값이다. |
| RQ2. 장르 임베딩은 어떤 이점이 있는가? | 같은 모델에서 장르 입력만 원-핫 벡터와 학습 임베딩으로 바꿔 예측 성능과 반복 실험 간 변수 중요도 순위의 안정성을 비교한다. |
| RQ3. 전체 곡에서 중요한 속성이 각 장르에서도 중요한가? | 전체와 장르별 SHAP 순위를 비교하고, 트리 모델에서 관찰한 장르별 차이가 딥러닝 모델에서도 나타나는지 확인한다. |

아티스트 인지도, 마케팅, 플레이리스트 노출은 입력에 포함되지 않는다. 두 모델의 성능이 비슷하다면 현재 입력으로 얻은 개선 폭이 작다고 해석한다. 이 실험만으로 오디오 속성이 제공하는 정보의 이론적 상한을 정할 수는 없다. [제안서, 6~7쪽 및 11쪽](prepare/proposal_music_popularity_xai-1.pdf)

## 데이터셋과 학습 표본

주 데이터는 zaheenhamidani가 Kaggle에 공개한 *Ultimate Spotify Tracks DB*의 정적 스냅샷이다. 같은 버전의 파일로 전 실험을 수행할 수 있고, 오디오 속성과 장르가 같은 행에 있어 장르별 분석에 필요한 정보를 별도로 결합할 필요가 없다. 프로젝트의 데이터셋 소개에 따르면 원본 규모는 232,725개 트랙 × 18열이며, 입력은 오디오 속성 17개와 장르, 목표값은 0~100점의 인기 지수다. 제안서는 장르 수를 26개로 제시한다. 기반 논문이 분석한 표본은 232,442건이다. 두 자료의 수집 시점과 트랙 구성이 실제로 일치하는지는 데이터 버전을 확보해 확인할 사항이다. [Kaggle 배포 페이지](https://www.kaggle.com/datasets/zaheenhamidani/ultimate-spotify-tracks-db) · [제안서, 8~11쪽](prepare/proposal_music_popularity_xai-1.pdf) · [기반 논문](https://doi.org/10.1016/j.jbusres.2026.116197)

| 역할 | 제안서에 열거된 항목 | 사용 방식 |
|---|---|---|
| 수치 입력 10개 | danceability, energy, loudness, speechiness, acousticness, instrumentalness, liveness, valence, tempo, duration | 학습 시 곡의 리듬·음향·정서·길이를 표현한다. 조정안을 표시할 때는 원래 단위를 사용한다. |
| 범주 입력 4개 | key, mode, time signature, genre | 조성·선법·박자·장르를 범주로 처리한다. 장르는 성능 및 설명을 나누어 보는 기준이기도 하다. |
| 목표값 | popularity | 0~100점의 회귀 레이블이다. 0점 곡도 분포와 오차를 따로 집계한다. |
| 식별 정보 | 트랙 ID, 곡명, 아티스트명 등 실제 파일에 있는 식별 열 | 중복 검사와 분할에 사용한 뒤 예측 입력에서 제외한다. |

**입력 열 확인.** 소개문의 ‘오디오 속성 17개 + 장르’를 모두 입력으로 세면 18열이 되어 목표값과 식별 열을 포함한 원본 열 수와 맞지 않는다. 제안서 9쪽에 이름이 명시된 입력은 위 표의 수치형 10개와 범주형 4개다. 구현 첫 단계에서 CSV 헤더를 대조해 입력·목표값·식별 열을 구분하고 최종 입력 수와 단위를 데이터 사전에 기록한다. 중복 제거 후 행 수, 실제 장르 수, 인기 0점의 비율도 이때 산출한다. 대체 후보로는 Spotify Charts 일별 Top 200과 Million Song Subset이 있다. 대체 시에는 인기 지수와 장르·오디오 열의 제공 여부를 점검하고 과제 및 비교 기준을 다시 정해야 한다. [제안서, 8~10쪽](prepare/proposal_music_popularity_xai-1.pdf)

## 메인 파이프라인

1. **정제와 분할.** 원본의 결측, 범위, 완전히 중복된 행, 여러 장르에 중복 수록된 트랙 ID를 확인한다. 같은 트랙의 행은 같은 분할에 묶는다. 80%를 학습용으로, 20%를 최종 평가용으로 보관한다. 학습용에서만 10겹 교차검증을 수행하고 결측 대체·수치 스케일링·범주 사전도 각 학습 폴드에서 맞춘다.
2. **인기 예측.** 선형 회귀로 단순 기준을 세우고 튜닝한 RF와 LightGBM으로 비선형 기준을 얻는다. FT-Transformer는 수치·범주 변수를 각각 토큰으로 만들어 변수 사이 상호작용을 학습한다. TabTransformer는 장르·조성 등 범주 임베딩을 문맥화한 뒤 수치 특성과 결합해 점수를 출력한다. 두 구조와 장르 표현 방식을 비교하며, 1D-CNN은 제안서의 선택 실험이다.
3. **예측 설명.** 트리 모델은 TreeSHAP, 딥러닝 모델은 구조와 호환되는 DeepSHAP 또는 기울기 기반 기여도 방법을 사용한다. 같은 평가 곡과 참조 표본을 사용해 곡별 기여도를 구한 뒤, 전체 및 장르별로 평균 절댓값을 집계한다. 이 값은 중요도 순위에 쓰고, 개별 곡의 점수를 올리거나 내린 방향은 부호 있는 기여도로 읽는다. 원-핫 열이나 임베딩 차원의 기여도는 원래 변수 단위로 합산한 뒤 비교한다.
4. **곡별 조정안 탐색.** 아티스트가 유지할 속성을 고정하고, 바꿀 수 있는 속성과 허용 변화량을 지정한다. 장르별 학습 표본에서 관찰된 범위 안에서 제약 베이지안 최적화로 예측 점수가 높은 조합을 찾는다. 장르를 유지한 소폭 수정과 다른 장르의 특성을 일부 반영한 스타일 전환을 별개 시나리오로 계산한다. 실제 데이터가 뒷받침하는 장르와 속성 조합만 사례에 사용한다.
5. **조언 카드 생성.** 각 후보에 대해 정체성을 보존하려고 고정한 속성, 바꿀 속성의 원래 값과 제안값, 변경 전후의 예측 점수를 표시한다. **Δpopularity = 변경안의 예측 점수 − 원곡의 예측 점수**로 계산한다. 두 점수는 같은 모델에서 얻는다. 아티스트와 레이블은 장르 유지안과 스타일 전환안이 각각 요구하는 변경 폭과 예상 이득을 비교해 어떤 편곡을 시도할지 결정할 수 있다.

**제안서의 카드 예시.** 인디 포크 곡의 acousticness를 0.85로 유지하면서 energy를 0.25에서 0.40으로, valence를 0.30에서 0.40으로 높인다. 예시 카드는 41점에서 52점으로의 변화(+11점)를 보여준다. 인디 포크에서 포크 팝으로 옮기는 안은 더 큰 변화의 예다. 장르명과 수치는 설명용이며, 실제 카드는 확보한 데이터와 학습한 모델로 계산한다. [제안서, 5쪽](prepare/proposal_music_popularity_xai-1.pdf)

## 구현 순서와 완료 기준

다음은 제안서의 실험을 실행하기 위한 구현안이다. 모델 선택과 튜닝에는 학습 데이터만 사용하고, 최종 평가에서는 모든 모델에 동일한 테스트 트랙을 사용한다.

| 단계 | 구현 작업 | 완료 기준과 산출물 |
|---|---|---|
| 1. 데이터 탐색 | 원본 버전과 헤더 기록, 중복 유형별 건수 집계, 장르별 표본 수와 인기 분포 확인 | 데이터 사전, 정제 전후 행 수, 0점 비율, 재현 가능한 분할 목록 |
| 2. 기준선 재현 | 선형 회귀·RF·LightGBM을 같은 입력으로 학습하고 학습 폴드에서 하이퍼파라미터 선택 | 모델별 교차검증 성적과 설정, RF 문헌값과 차이가 생길 때 점검할 정제·분할 조건 |
| 3. 딥러닝 비교 | 두 Transformer의 입력·회귀 출력을 구현하고 장르 표현만 바꾸는 대조 실험 수행 | 같은 분할·튜닝 예산에서 얻은 모델별 성능표, 원-핫 대비 임베딩의 성능 차이 |
| 4. 오차와 설명 분석 | 모델을 확정한 뒤 홀드아웃 평가, 장르별 오차 집계, 모델·반복 실험별 중요도 순위 비교 | 전체 RMSE·MAE·R², 장르별 표본 수와 오차, 인기 0점/양수 곡별 오차, 전체·장르별 기여도 그림 |
| 5. 처방 데모 | 사례 트랙별 고정·조정 속성을 정하고 장르 유지와 스타일 전환 후보를 탐색 | 변경안이 제약을 만족하는지 확인한 조언 카드, 원곡 대비 예상 점수 차이 |

RMSE는 큰 예측 오차에 더 큰 가중치를 주고, MAE는 평균적으로 몇 점 차이가 나는지 보여준다. 두 지표는 낮을수록 좋고, R²는 높을수록 좋다. 결과 보고서에는 문헌값과 같은 분할에서 직접 학습한 RF 성적을 따로 표시한다. 최종 결론은 Transformer의 개선 폭, 장르 표현에 따른 설명의 안정성, 실제 제약 안에서 제시할 수 있었던 곡별 변경안을 세 연구 질문과 연결해 작성한다. [제안서, 6쪽 및 12쪽](prepare/proposal_music_popularity_xai-1.pdf)
